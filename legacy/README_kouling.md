# 口令第二八六条：高倍 SP 平局腿「乱推」事故与因子校准

## 一、事故：平局腿是历史亏损的唯一元凶

回测 `data/highsp_review.json` 全部 73 条完赛腿：

| 腿类型 | 命中 | 平均赔率 | 单关 ROI |
|---|---|---|---|
| 平局腿 | 9/31 = **29.0%**（含作废口径 9/49=18.4%） | 3.43 | **89.4%** |
| 主推腿 | 30/42 = **71.4%** | 1.81 | **120.7%** |

**按赔率分层的平局腿命中率（决定性证据）**：

| 平局赔率 | 命中 | |
|---|---|---|
| <3.0 | 3/5 = 60.0% | |
| 3.0~3.5 | 6/18 = 33.3% | ← 唯一正期望档 |
| 3.5~4.0 | 0/2 = 0% | |
| **≥4.0** | **0/6 = 0%** | ← 全负 |

**根因**：旧 `passHighBlock` 的平局入选条件是 `平局率 ≥ 25%`——
只看模型概率，不看比赛本身的平局倾向，于是"为了凑倍数"挑高赔率平局
（曼城vs巴黎圣曼推 4 次、苏格兰vs瑞士推 4 次、加拉塔萨雷vs巴萨 6.6、巴黎圣曼vs巴萨 4.3），
而高赔率恰恰意味着市场认为不会平，历史证明市场是对的。

## 二、修复：平局腿必须过「因子关」

用 129 场真实赛果建校准表（因子 = 预测总进球 × top3 中平比分个数）：

| 因子格子 | 样本 | 实际平局率 | 模型均值 | 偏差 |
|---|---|---|---|---|
| tot<2.5 & nd=2 | n=21 | **42.9%** | 29.6% | **+13.2pt** |
| tot<2.5 & nd=1 | n=22 | 22.7% | 26.7% | −4.0pt |
| tot≥2.5 & nd=1 | n=36 | 22.2% | 22.4% | −0.2pt |
| tot≥2.5 & nd=0 | n=28 | **10.7%** | 16.1% | −5.4pt |

**入选规则（两条都要满足）**：
1. 因子 edge ≥ 6pt（校准概率 − 市场隐含概率）
2. 平局赔率 < 3.5（历史 ≥3.5 档 0/8 全负）

## 五、铁律（新增）

1. **平局腿不得"为了凑倍数"选取**，必须过因子关 + 赔率关。
2. **赔率 ≥4.0 的平局腿一律不碰**（历史 0/8）。
3. **校准概率 = 市场隐含 + 因子偏差**，不得直接用历史边际频率当绝对概率（会系统性高估）。
4. **作废记录必须标 `void:true` 并排除出统计**，不得计入分母。
5. 样本 <25 的因子格子必须向基准收缩（K=6~12），并在文案里说明不显著。

## 第二八九条（2026-10-21 21:00）· 北单静默失败的真正根因 + 平局腿零通过

### 一、北单"解析出 0 场"的真正根因：解析器的贪婪 \s*

`_grab_bjdc.py` 里的行切分正则写成：

```python
re.split(r'\n\s*(\d{1,3})\s*\n\s*\n\s*', body)
```

`\s*` 是贪婪的，它会把 `"37\n \n \n J2联赛"` 里的换行和空格**全部吃掉**，
随后再要求 `\n\s*\n\s*` 就永远匹配不上 → 整个 split 失效 → 解析出 0 场。

**修法**：先把全文做一次 `lines=[l.strip() for l in raw.split('\n') if l.strip()]` 归一化，
再用"序号 → 联赛 → `^\d{1,2}:\d{2}$` 时间"三段式顺序扫描，抓到 98 场（原 44 场里只有 15 场能回填）。

> 教训：**\s* 能跨行**。凡是要用正则切 HTML 行的地方，先归一化再匹配，不要指望 \s* 只吃空格。

### 二、北单日期口径：区块日 +1

500 北单页的日期区块是"当日 10:00 — 次日 10:00"。
所以区块头写 `2026-10-21 星期三`，里面 `00:35 / 02:50` 的比赛**实际是 10-22 凌晨**，
只有 `11:50 / 17:50 / 18:20` 才是 10-21 当天。

判据：`tm 小时 < 10 → 实际日期 = 区块日 + 1`。
之前没做这步，把凌晨场当成"当天已过期"给丢了。

### 三、北单 sp 列不可信（第二次确认）

500 北单页最后三列对**未开赛场次**给出的是 `1.03 / 103.10 / 45.14` 这类值，
不可能是 SP（欧赔 4.86 的凯拉特，主胜 SP 不可能是 1.03）。
**继续沿用 287 条的结论：只用 `eu`（99 家平均欧赔）建模，sp 字段一律不采信。**

1. 修产物必须同时修模板，否则下次重跑复发；

## 第二九八条 · 任九"点不动"的真正根因（2026-10-23 用户反馈"什么都点不动"）

## 第三〇三条 · 北单 399 场全部显示「胜平负 SP 未获取」——类型不匹配（2026-10-23）

**现象**：北单 tab 399 场全部显示红色「胜平负 SP 未获取」，不推方向、不给概率、不给比分。

**根因链（三处叠加）**：
1. `enrich()` 里 `t['odds'] = ['%.2f' % x for x in t['o']]` → **字符串**数组
2. `make_live.py` 里 `_m['sp'] = _odds`（取的是 odds）→ sp 变成 **字符串**
3. 渲染层 `renderBjdc`：`_spOk = m.sp.every(v => typeof v==='number' ...)` → 字符串一律 False
   → `m.noOdds=true; m.conf=0; m.rec=null; m.top3=[]` → **399 场全空**

**修复**：
- `make_live.py`：sp 统一 `float()` 转换，优先取 `o`（数字）→ `sp` → `odds`
- 渲染层：`_spNum = (m.sp||[]).map(v=>Number(v))`，兼容字符串与数字

**铁律**：
> **数据类型要在写入侧和读取侧同时对齐。** 
> `node --check` 查语法、`typeof` 判定只在运行时生效——
> 「有值但类型不对」是最隐蔽的一类 bug：数据层 100% 有值，页面上 100% 显示"未获取"。
> 交付前必须**浏览器实跑 + 数页面上的可见元素个数**，不能只看 JSON 里有没有字段。

## 第三一六条 · 教练/球队资料接口实测（2026-10-25）

用户提示两处：`team/getTeamInfoV1.qry?uniformTeamId=X`、`qdzl/?tid=196`。实测结论：**都拿不到教练**。

### 1) getTeamInfoV1 —— 不在 WAF 白名单（决定性对照）
穷举 5 个 BASE 前缀 × 3 种参数写法，共 15 组，**全部 `Failed to fetch`**：

```
uniform/football/  uniform/team/  team/  uniform/  football/team/
×  getTeamInfoV1.qry?uniformTeamId=
   getTeamInfoV1.qry?source=web&uniformTeamId=
   team/getTeamInfoV1.qry?uniformTeamId=
```

**为什么判定"不在白名单"而不是"限流"**：
- 每个目标请求之后都插入基准接口 `getMatchFeatureV1`，**5 次基准全部 200**
- 乱命名对照 `getZzzNotExistV1.qry` 同样是 `Failed to fetch`
→ 白名单内的接口（即使参数错）返回 200/403；白名单外的直接 TCP 断连报 Failed to fetch。
→ 二者行为完全一致 ⇒ getTeamInfoV1 不在白名单。

### 2) qdzl 页面 —— 403 policy_default_denied
```
www.sporttery.cn/qdzl/?tid=196              403
www.sporttery.cn/qdzl/index.html?tid=196    403
www.sporttery.cn/jc/qdzl/?tid=196           403
```
同源 probe 页内用 XHR + Referer 也一样 403。**导航和 XHR 都被拦**，不是同源问题。

### 3) 已通的 4 个官方接口里确实没有教练
全量 grep `data/intel.json`（33 场 × inj/feat/tbl/head）：
```
教练 / coach / Coach / 主帅 / manager  →  出现 0 次
总字段 79 个，无任何教练相关字段
```

### ★ 方法论沉淀（比结论更值钱）
**a. 判定"接口不存在"必须做插桩对照，不能只看失败**
```
目标 → 基准 → 目标 → 基准 → 目标 → 基准
```
只有"每个目标之后基准都 200"才能排除限流。上一轮我 9 个请求全 Failed to fetch 就差点误判，实际是整体限流——**那次结论作废**。

**b. `Failed to fetch` 有两种截然不同的成因，必须先区分**
| 现象 | 成因 | 处置 |
|---|---|---|
| 目标失败 + 基准也失败 | 限流 | 冷却 100~150s 重跑 |
| 目标失败 + 基准 200 | endpoint 不在白名单 | 换名/放弃，别再重试 |

**c. 建立页面 origin 用 `route().fulfill()` 伪造，别 goto 真实首页**
首页重、常被限流拖到 40s+ 超时。伪造 `https://www.sporttery.cn/probe` 后 fetch 白名单接口照样 200，且快。

### ★ 数据资产（备用）
`data/_tid316.json` 已存 62 场的 `uniformTeamId`（主/客），
来自 `getInjurySuspensionV1` 返回里的 `uniformTeamId` / `teamShortName`。
**哪天 getTeamInfoV1 通了，直接拿这批 id 批量打，不用重新找。**

### 结论
教练仍无源，页面继续标「未采集」，**不编造人名**。

## 第三二七条　fdb4.io 调研结论（2026-10-26，用户提示去看）

### 一、它是什么
- 站点：https://fdb4.io ，个人项目，专做「赛果 + 平局统计」。
- 库容（首页实测）：**547,074 场**、15,148 队、305 赛事；全站平局率 **24.3%**（俱乐部 24.5%）。
- 五mission：连胜查找 / 赛果统计 / 平局模型 / API / MCP。

### 二、免费 vs 付费（实测，别搞混）
- **免费**：所有 HTML 页面（`/fixtures`、`/streaks`、`/match/{id}`、`/predictor`、`/teams`、`/results`）；MCP 里 6 个工具免 key（`list_teams`/`get_team`/`get_team_streaks`/`list_tournaments`/`list_countries`/`search_results`，60 次/小时/IP）。
- **付费**：`/v1/*` 全部要 key（1 分=1 美分，注册送 10 分）；MCP 5 个付费工具 **`head_to_head` 在其中**（另：predict_draws / get_team_prediction / get_draw_model / top_streaks）。
- **所以：历史交锋仍是付费的，fdb4 不能白嫖 H2H。**

### 三、★最重要收获：80 万样本实证「不反弹」
我的旧结论是「连败反弹证据不足（n=13，CI±27pt）」，样本太小，只有 8/10 信心。
fdb4 专页 https://fdb4.io/is-a-draw-due 给出按「平局债务 E」分档的**下一场实际平局率**：

| E（平局债务） | 样本(队-场) | 实际 | 模型 | 差 |
|---|---|---|---|---|
| 0–0.5 | 413,849 | 25.45% | 25.33% | +0.12 |
| 0.5–1 | 182,076 | 25.56% | 25.14% | +0.41 |
| 1–1.5 | 99,726 | 25.35% | 24.96% | +0.38 |
| 1.5–2 | 54,607 | 25.47% | 24.88% | +0.58 |
| 2–3 | 44,207 | 25.13% | 24.76% | +0.37 |
| 3–4 | 11,406 | 25.11% | 24.62% | +0.49 |
| 4–6 | 2,770 | 25.42% | 24.53% | +0.88 |
| 6+ | 91 | 24.18% | 26.07% | −1.90 |

合计约 **808,732 队-场**，各档差异 +0.12 ~ +0.88pt，最高分组也只画 25.0%（全站 24.3%）。
→ **结论升级为：无平局连胜 / 平局债务 / 连败，对下一场平局（或胜负）概率基本无提升。**
→ 「反弹诉求」只能当叙事，不能当加分项。信心分由 8/10 升到 **9/10**。
→ 站点原文：「Overdue describes the run, not evidence that a draw is coming: over a million team-matches, neither N, E nor the score raises the next match's draw chance.」

### 四、`/match/{id}` 免费页能给什么（实测 match/130954、3959771、427073、190560）
一场给全：
- Elo 双方评分 + 差值 +「该差值下的历史平局率」+ 样本数
- **Dixon-Coles 期望进球（主-客）** + 主/平/客 三项概率
- **Blended draw chance**（进球模型 75% + Elo 差值 25%，对数几率尺度混合，544,576 场调参）
- **Logistic draw chance**（五特征逻辑回归 + isotonic 校准）及 95% 区间
- 每队：N 无平局连胜、Max N 历史最长、E 平局债务、p50/p100 平局率、历史总平局率
- 站点自述：在 160,869 场有赔率比赛中，进球模型略逊于博彩公司。

→ 价值：**独立的第二平局概率**（可与我们模型交叉验证）。任九最怕平局，这个交叉验证有实际意义。

### 五、卡住的环节（诚实记录）
- **未开赛场次的 match_id 拿不到**：`/fixtures` 只给日期+队名+赔率，web_fetch 取不到链接；搜索引擎只能搜到**已结束**的场次（130954=2025-05-11，非 2026-10-26 那场）。
- 沙盒 `curl fdb4.io` **403**（WAF），只有 web_fetch 通 → 无法 POST 调 MCP。
- 免 key 的 MCP 工具（`search_results` 能按队名+日期查 match_id）**本机用不了**，需要用户侧客户端。

### 六、结论与待办
1. fdb4 **可以**补「独立平局概率第二意见」，但批量接需要 key（1 美分/场，任九14场≈0.14元/期）。
2. fdb4 **不能**补伤停/教练/阵型（它只有赛果）。
3. **已可免费采用**：80 万样本的「不反弹」实证，已并入本条，分析文案按此表述。

## 第三三〇条 · 运行时 undefined 与「守卫假绿」（2026-10-26）

### 现象
用户反复反馈「任九 01-04 还是没有」。查下来：
**场次其实在**（`__SFC_PICK__` / `__SFC_NOW__.matches` 都是 14 场，浏览器渲染也有大田市民/京都不死鸟/北京国安/叻武里）。
但界面显示成：
```
主第null · 客第null
📌 推荐 　把握 undefined%　⚽ 总球 undefined　平局 undefined%
```
用户看到满屏 null/undefined，自然判定为「没有」。

### 根因：渲染层无条件拼接
```js
'主第'+t.hrank+' · 客第'+t.arank        // hrank=null → "主第null"
'把握 <b>'+t.main_p+'%</b>'             // main_p=null → "undefined%"
```
01-04 亚冠未开盘，hrank/arank/main_p/tot/draw_p 全是 null。

### 修法（index.html + index_live.html 都改，第三一〇条）
1. 排名：`typeof t.hrank==='number' && typeof t.arank==='number'` 否则显示「排名未公布」
2. 推荐行：无赔率时整行换成「📌 无市场定价 → 不给推荐、不编概率」，不渲染数字

### ★ 更重要的：守卫为什么一直报绿
**G5 守卫读的是静态 HTML 文件文本**：
```python
s = io.open(LIVE).read()
'und<br>efined' not in s   # 必然 True
```
但 `undefined` 是 **JS 运行时拼接出来的**——源码里是正常代码
`'把握 '+t.main_p+'%'`，静态文件里根本没 "undefined" 这个词。
**静态检查永远不可能抓到运行时脏值。这是原理性缺陷，不是漏配。**

`verify()` 也有缺陷：只在最后查一次 `document.body.innerText`，
只看到最后停留的那个 tab，其余 tab 从未被检查。

### 修法（refresh.py）
1. **verify 改成逐 tab 扫描**：每个 tab 点击后立刻查该 tab 的 innerText
   ```python
   _t = pg.evaluate('document.body.innerText')
   for _b in ['undefined','NaN','[object Object]','null']: ...
   ```
2. **G5 改名标注局限**：「静态文本无undefined(不覆盖运行时)」

### 验证：改完守卫立刻抓出遗留问题
改后第一次跑 verify 就抓到 `tab[data-p|dlt] 含 undefined × 1`
—— 是**大乐透的「每号均值 undefined」**，我之前提过但一直没修。
根因：`__DLT_PICK__` 里**根本没有 `ef` 字段**（keys 只有
issue/date/n/plans/src/last/mystic），渲染却直接用 `P.ef`。

修法：`ef` 缺失时按 `期数×5÷35` 算理论均值
（7期开35个号次 ÷ 35个号码 = 每号1.0次，**这是数学事实不是编造**）。

### 铁律（新增）
1. **静态文本检查不能替代运行时检查**。凡是 JS 拼接出来的值，
   必须在浏览器里逐 tab 扫 innerText 才算验证过。
2. **守卫报绿 ≠ 没问题**。守卫报红时先怀疑守卫（第三〇六条），
   守卫报绿时也要问「它真的有能力发现这类问题吗」。
3. **字段缺失不能渲染成 undefined**。渲染前判 `typeof x==='number'`，
   缺失就显示「未公布/待核实」，绝不让 null 直接进模板字符串。

## 第三三三条 · 解析层丢数据：任九 01-04 反复"消失"的真因（10-26）

## 第三三五条（bf比分页空壳误报 / 定时更新后直接交付文件）

**现象**：`refresh.py all` 报 `tab[data-p|bf] bodyLen=1837/需3000 << 空壳`，但打开页面比分数据是全的。

**根因**：`renderBf()` 的卡片来自竞彩在售场次 `window.__LIVE__.matches`，

**教训**：凡"字符量随条目数变化"的 tab，都不能用固定阈值判空壳——

**修法**：`need = max(900, 场次數*350 + 300)`，实测 4 场 → 1700，1837 通过；场数多时自动收紧。

**连带**：`sxtwl` 模块会莫名丢失（`ModuleNotFoundError`），导致大乐透玄学静默不出注。

**定时交付**：每日 06:00 定时任务「每晨竞彩更新与自检」跑完后**直接把文件交付给用户**

**06:00 的数据边界（重要）**：竞彩新场次白天才放（lottery.gov.cn 凌晨显示"未开售"），

## 第三五六条 · 大乐透玄学：八卦爻表错值导致崩溃（+ sxtwl 第 5 次丢失）

### 一、崩溃现场
```
_dlt_mystic282.py line 103: KeyError: '阳阴阴'
```
`INV[flip(GUA_LINES[gua_dn], yao)]` —— flip 出一个三爻组合后查 INV 查不到。

### 二、根因：表里有两个键的值重复
```python
GUA_LINES = {'乾':'阳阳阳','兑':'阴阳阳','离':'阳阴阳','震':'阴阴阳',
             '巽':'阳阳阴','坎':'阴阳阴','艮':'阴阴阳','坤':'阴阴阴'}
#                    兑↔巽 互换 ↑       震 写成艮的值 ↑  艮 重复 ↑
```
8 个卦名只对应 **7 个不同的爻串**，而 `INV = {v:k for k,v in GUA_LINES.items()}`
只有 7 个键。只要变卦 flip 出缺失的第 8 种（'阳阴阴'），直接 KeyError。

三爻自下而上的正确值（初爻→上爻）：
```
乾111 兑110 离101 震100 巽011 坎010 艮001 坤000
```
即：兑='阳阳阴'、巽='阴阳阳'、震='阳阴阴'、艮='阴阴阳'。已按此修正。

### 三、sxtwl 丢失是第 5 次
模块 `sxtwl`（四柱）与 `lunar_python`（二十八宿/值神）会莫名丢失，
**缺失不报错，只表现为玄学字段全 None + dlt_pick.json 不生成**（静默不更新）。

### 四、铁律
**字典反转（{v:k for k,v in D.items()}）前必须断言 len(反转表) == len(D)。**
值重复时反转表会静默少键，错误在很后面才以 KeyError 形式爆出来，且看不出是表的问题。

### 事故 A：`name_eq` 等长队名全判相等（全项目系统性误配）

`_lib.py` 原写法：

```python
a, b = min(x, y, key=len), max(x, y, key=len)
return len(a) >= 2 and a in b
```

**两串长度相等时，`min` 和 `max` 返回的是同一个对象** → `a in b` 变成
`a in a` → **恒为真**。结果：任意两个等长队名都被判相等。

实测（修复前）：

```
name_eq('伊普斯','查尔顿')  → True   ← 完全不相干
name_eq('诺丁汉','诺维奇')  → True
```

后果：任九赛果匹配时 112 场里 92 场「歧义」（每场匹配到 6~7 个候选）。
修复：长度相等时保留原顺序。

```python
a, b = (x, y) if len(x) <= len(y) else (y, x)
```

修复后 8/8 用例通过，任九匹配歧义 92 → 0。

## 第三六四条（2026-11-03）★ 澳客任九落盘的前导空格坑 + 北单"空壳"是波动不是永久

**现场**：26157 期（欧冠8 + 英冠6，停售 11-03 22:00）澳客页抓到 14 场全有欧赔，

各段正则单独测试全部 OK，拼起来却 0 场。

**根因**：`RE_SFC` 里 `\[(?P<hr>\d+)\]` 前面**没有 `\s*`**。
web_fetch 转出的 markdown 主队行带前导空格：

```
\n \n\n \n [1]土超加拉塔\n VS\n 斯图加[11]德甲\n
            ^ 这个空格
```

`(?:[^\n\[]*\n){0,6}?` 消耗完三行后，游标停在 ` [1]` 的空格上，
`\[` 匹配不上 → 整条丢弃 → 静默 0 场，**不报错**。

**修法**：落盘后统一 `re.sub(r'\n\s+(\[\d+\])', r'\n\1', s)` 去掉主队行前导空格。
（改正则加 `\s*` 也可，但 RE_SFC 是全局共用，改落盘更安全。）

**新规矩**：**任何手工落盘 raw/ 的澳客/500 文本，落盘后必须立刻 `parse_*` 验证场数**，
不能等到 build 才发现是 0。这是"解析层丢数据"第 5 次复发（第三三三条、第三五六条同类）。

## 第三七二条：战意由「排名 + 积分」推导，不是拍脑袋贴标签

**小组榜口径**：组内名次 + 积分 + 胜平负推定已赛轮次；总轮次优先读
`totalRounds`，否则按常规双循环推定（4队→6轮 / 3队→4轮），并在文案里
明写「总轮次按常规双循环推定」。剩余可得分 = 3 × 剩余轮次。
比较「与第2名 / 第3名 / 末位」分差是否被剩余分数追不上：
- 已锁定前二（领先第3名 > 可追分）→ 战意偏低，轮换/练兵风险
- 落后第2名 > 可追分 → 战意低，荣誉战（末位且距安全线≤3 转述为保级倾向）
- 相邻分差 ≤3 或同分 → 战意高/极高，卡位生死战
**不绑定具体晋级名额**（各赛季规则不同），只判断「还能不能追」。

**联赛阶段口径**（36队单榜）：按通用 1-8 直通 / 9-24 附加 / 25+ 出局，
取第8、第24名积分作分界线，同样用剩余分数判锁定/出局。规则若变以官方为准。

差 2 档以内只作提示，**不自动改概率**。

## 第三七三条：★ 「第一次可以、第二次不行」的机制与根治

用户明确点名过。复盘下来不是数据反复，是**我把三种状态混着说**：

| 状态 | 含义 | 稳定性 |
|---|---|---|
| A 链路跑通 | 本地样例/离线文件能算出段 | 恒真，可复现 |
| B 源实抓成功 | 联网真拿到数据 | **波动**，取决于出口 IP / WAF / 时段 |
| C 快照在盘 | `data/uel_rank.json` 等文件确实存在 | 取决于用户是否丢进来 |

把它说乱的三个具体机制：

1. **A 说成 B**。用临时样例验证「段能出」，汇报时没讲是样例 → 用户看到
   「有了」，清掉样例后变成「没了」。
2. **样例验证污染模板/产物**。`_radar310.py` 会同时写 `index.html` 和
   `index_live.html`，直接跑样例就把假段注入进去，看起来像真数据。
   → 已加 `--dry`（只算不写）；**任何样例/链路自检必须走 dry**，
   验完仍要 `grep 【战意】/【欧战排名】` 确认 0 残留。
3. **B 写成永久结论**。500 北单 11-01 空壳、11-02 通、11-12 又空；
   竞彩官方伤停接口 567 重试后 200；FotMob 一直 403 而另一台机 200。
   → 源状态必须**带日期**，写「今天 403」，不写「这个源不通」。

**以后每次更新的固定格式**（不许省）：
```
链路 A：✅/❌   实抓 B：✅/❌（日期 + 通道数）   快照 C：在盘/缺
页面段数：N 处（缺 C 就是 0 处，如实说）
```
